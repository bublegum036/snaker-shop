## Запуск магазина

Для уже подготовленного окружения на macOS/Linux доступны команды **из корня
репозитория**:

```sh
make dev       # PostgreSQL, проверка настроек/миграций, API и фронтенд
make status    # готовность API, страницы и прокси с доступом к БД
make stop      # из другого терминала; завершает только общий запуск
make check     # линтеры, сборка и 157 изолированных сценариев фронтенда
```

`make dev` работает в текущем терминале и показывает логи обоих серверов.
Каталог: http://127.0.0.1:4200, Swagger: http://127.0.0.1:8000/docs.
Остановить можно также Ctrl+C. Занятые порты не освобождаются автоматически:
если серверы уже запущены вручную, завершите их в прежних терминалах или
выберите отдельные порты:

```sh
make dev API_PORT=18001 WEB_PORT=14201
```

Нужны работающий Docker Desktop, backend `.venv` с requirements.txt и `.env`,
а также frontend/node_modules и совместимый Node.js. Скрипт сначала ищет
версию из frontend/.nvmrc в NVM_DIR (по умолчанию ~/.nvm), затем Node из PATH.
Зависимости, ключи и `.env` автоматически не устанавливаются и не заменяются.
Для первой подготовки следуйте инструкции ниже. Если схема отстаёт от кода:

```sh
make db        # поднять PostgreSQL через существующий Compose
make migrate   # явно применить подготовленные миграции
make seed      # явно добавить недостающие учебные товары
```

Обычный запуск только читает ревизию миграций; не применяет их и не вызывает
seed. `make stop` дожидается завершения фронтенда и API, но PostgreSQL оставляет
работать. Для отдельной остановки БД выполните `docker compose stop db` из
presentation/sneaker-practice; рабочий том сохраняется.

Команды реализованы в [Makefile](Makefile) и [scripts/dev.py](scripts/dev.py).
Supervisor — небольшой управляющий процесс: он запускает дочерние серверы,
следит за их завершением и принимает status/stop через локальный Unix-сокет
с ограниченными правами. Служебные файлы в `.local/dev/` исключены из Git.
Это не новый сервис приложения и не замена FastAPI, Vite или Pinia.
Если один сервер завершается, второй также останавливается. Одновременный
повторный общий запуск блокируется; PID-файлы и поиск чужих процессов по
имени/порту не используются. После SIGKILL повторный запуск удалит старый
сокет только после захвата блокировки; SIGKILL не гарантирует очистку дочерних
процессов, поэтому для обычной остановки используйте make stop или Ctrl+C.

`make status` показывает только управляемый запуск этого репозитория:
ready (код 0), starting/unhealthy/inactive (ненулевой код). Вручную запущенные серверы
не считаются управляемыми, даже если их адреса доступны. Без активного общего
запуска `make stop` безопасно возвращает inactive. Сокет создаётся после
подготовки БД, поэтому на раннем этапе запуска status ещё может быть inactive.
На Windows эти команды не проверены: скрипт использует Unix-сокет и flock.

Проверить сам управляющий скрипт: `make check-launcher` (6 тестов, временные
сокеты и собственные дочерние процессы, без рабочей БД). Проверено также
реальное поднятие/готовность/остановка на 18001/14201, отказ повторного запуска
и занятого порта; серверы на 4200/8000 сохранились. `make check` прошёл полностью.

Откройте терминал в presentation/sneaker-practice и выполните README этой папки: новый venv → requirements.txt → свой .env из .env.example → setup_jwt.py → Docker Compose → миграция → seed → uvicorn app.final_main:app. Нужны Python 3.11+ и Docker с Compose. Реальные проверки проведены на macOS/Python 3.13.3/PostgreSQL 17. Для первой установки пакетов и образа БД нужен интернет; сама HTML-презентация работает локально.

Виртуальные окружения, node_modules, локальные .env, кэши и рабочие данные БД не включены. Все .env.example, зависимости, миграции и seed сохранены: окружение и учебные данные создаются по инструкции.

## Проверка архива

ZIP проверен на целостность. MANIFEST.sha256 содержит SHA-256 каждого файла, кроме самого манифеста. После изменения файлов их суммы закономерно изменятся. В копии плана абсолютная ссылка на задание заменена локальной; необязательный браузерный проверочный скрипт использует собственный package.json вместо зависимости от другого проекта. Остальные исходники курса сохранены.
