# Vue-фронтенд магазина — этап F1

На первом этапе работает чтение каталога из FastAPI: загрузка, ошибка с повтором,
пустой список, карточки с ценой и доступными размерами. Пока загружаются первые
20 товаров. Фильтры, пагинацию, вход, корзину и заказы добавляем отдельными этапами.

## Запуск

Нужны Node.js `^20.19.0 || >=22.12.0` и запущенный бэкенд на `127.0.0.1:8000`
(инструкция: [backend README](../presentation/sneaker-practice/README.md)).
Из корня репозитория:

```sh
cd frontend
npm ci
npm run dev
```

Откройте http://127.0.0.1:4200. Каталог публичный, учётная запись не нужна.
`strictPort` не позволяет Vite молча переключиться на другой порт, если 4200 занят.

Браузер вызывает `/api/products?limit=20&offset=0` на порту 4200. Vite удаляет
префикс `/api` и передаёт запрос бэкенду на порт 8000. Это аналог `proxy.conf.json`
в Angular; CORS менять не требуется. Этот прокси работает только у dev-сервера.
Для будущего развёртывания потребуется аналогичный маршрут `/api` на веб-сервере.

## Архитектура и аналогии с Angular

```text
src/main.ts                   создание приложения, Router и Pinia (bootstrap)
src/App.vue                   общий каркас и RouterView (router-outlet)
src/router/index.ts           таблица маршрутов; сейчас только /
src/views/CatalogView.vue     страница: запрос и состояния загрузки/ошибки
src/components/ProductCard.vue карточка: принимает product и index через props
src/api/catalog.ts            интерфейсы ответа и функция getProducts (API-сервис)
src/styles.css                общие стили и адаптивная сетка
vite.config.ts                сборка, порт и dev-прокси
```

`<script setup lang="ts">` — логика компонента, `<template>` — его HTML.
`ref` хранит реактивное состояние: в TypeScript оно меняется через `.value`,
в шаблоне Vue раскрывает его автоматически. `computed` пересчитывается при
изменении зависимостей. `onMounted` запускает загрузку после появления страницы.
`v-if` выбирает состояние интерфейса, `v-for` выводит список; `:key` идентифицирует
элементы. `defineProps` задаёт входные параметры карточки, как Angular inputs.

API-функция использует встроенный `fetch`, а не отдельную HTTP-библиотеку.
Она проверяет HTTP-статус: `fetch` сам не считает 4xx/5xx исключением.
Интерфейс TypeScript описывает ожидаемый JSON, но не валидирует его в runtime.
Цена и размер приходят строками, как Decimal в Swagger. Перевод цены в Number
здесь нужен только для отображения: расчёт заказа остаётся на сервере.

Pinia установлена и подключена, бизнес-хранилищ пока нет: состояние каталога
нужно только этой странице. Хранилища пользователя и корзины появятся тогда,
когда данные понадобятся нескольким компонентам. Демо-счётчик генератора удалён.
Фото не выдумываются: при отсутствии картинки или ошибке загрузки показана заглушка.

## Проверка и границы этапа

```sh
npm run build
```

Команда проверяет TypeScript через `vue-tsc` и собирает `dist/`. Зависимости
фиксирует `package-lock.json`; `node_modules/` и `dist/` исключены из Git.
Для ручной проверки: открыть каталог, сверить товары со Swagger, нажать
«Обновить каталог» и проверить мобильную ширину. При недоступном API должна
появиться ошибка с кнопкой повтора; после восстановления API повтор загружает данные.

Исходники и архитектура этапа просмотрены и одобрены пользователем.
Изменения сохраняются локальным коммитом; публикация в сеть не настроена.

Проверено 14.10.2026: `npm ci --include=optional`, проверка TypeScript и
production-сборка прошли. В Chrome отображаются четыре реальных товара,
кнопка обновления повторно загружает каталог. Ответ `/api/products` через Vite
совпадает с прямым ответом FastAPI, код 200, X-Request-ID проходит через прокси.
Мобильная вёрстка и состояния ошибки/пустого списка пока отдельно не проверялись.

Основа: [Vue Quick Start](https://vuejs.org/guide/quick-start.html),
[настройка прокси Vite](https://vite.dev/config/server-options.html#server-proxy).
