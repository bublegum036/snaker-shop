# Vue-фронтенд магазина — этапы F1–F2

Работает каталог FastAPI: загрузка, ошибка с повтором, пустой список, карточки
с ценой и доступными размерами. Этап F2 добавляет поиск по названию, бренд,
размер в наличии, диапазон цены, сброс и пагинацию (3/12/24 товара на странице).
Вход, корзину и заказы добавляем следующими этапами.

## Запуск

Нужны Node.js `^20.19.0 || >=22.12.0` и запущенный бэкенд на `127.0.0.1:8000`
(инструкция: [backend README](../presentation/sneaker-practice/README.md)).
Из корня репозитория:

```sh
cd frontend
npm ci
npm run dev
```

Откройте http://127.0.0.1:4200. Каталог публичный, учётная запись не нужна.
`strictPort` не позволяет Vite молча переключиться на другой порт, если 4200 занят.

Браузер вызывает `/api/products?limit=13&offset=0` на порту 4200: это первая
страница из 12 товаров плюс одна запись для проверки следующей страницы. Vite удаляет
префикс `/api` и передаёт запрос бэкенду на порт 8000. Это аналог `proxy.conf.json`
в Angular; CORS менять не требуется. Этот прокси работает только у dev-сервера.
Для будущего развёртывания потребуется аналогичный маршрут `/api` на веб-сервере.

## Архитектура и аналогии с Angular

```text
src/main.ts                   создание приложения, Router и Pinia (bootstrap)
src/App.vue                   общий каркас и RouterView (router-outlet)
src/router/index.ts           таблица маршрутов; сейчас только /
src/views/CatalogView.vue     страница: применённые фильтры, загрузка, пагинация
src/components/CatalogFilters.vue форма: черновик полей, валидация, событие apply
src/components/ProductCard.vue карточка: принимает product и index через props
src/api/catalog.ts            типы, getProducts/getBrands, query-параметры
src/styles.css                общие стили и адаптивная сетка
vite.config.ts                сборка, порт и dev-прокси
```

`<script setup lang="ts">` — логика компонента, `<template>` — его HTML.
`ref` хранит реактивное состояние: в TypeScript оно меняется через `.value`,
в шаблоне Vue раскрывает его автоматически. `computed` пересчитывается при
изменении зависимостей. `onMounted` запускает загрузку после появления страницы.
`v-if` выбирает состояние интерфейса, `v-for` выводит список; `:key` идентифицирует
элементы. `defineProps` задаёт входные параметры карточки, как Angular inputs.

API-функция использует встроенный `fetch`, а не отдельную HTTP-библиотеку.
Она проверяет HTTP-статус: `fetch` сам не считает 4xx/5xx исключением.
Интерфейс TypeScript описывает ожидаемый JSON, но не валидирует его в runtime.
Цена и размер приходят строками, как Decimal в Swagger. Перевод цены в Number
здесь нужен только для отображения: расчёт заказа остаётся на сервере.

Pinia установлена и подключена, бизнес-хранилищ пока нет: состояние каталога
нужно только этой странице. Хранилища пользователя и корзины появятся тогда,
когда данные понадобятся нескольким компонентам. Демо-счётчик генератора удалён.
Фото не выдумываются: при отсутствии картинки или ошибке загрузки показана заглушка.

## F2: как работают фильтры и пагинация

`CatalogFilters.vue` хранит черновик через `reactive`. `v-model` связывает поля
с объектом формы (аналог двусторонней привязки Angular). Для `type="number"`
Vue автоматически приводит ввод к числу, но очищенное поле остаётся пустой
строкой, поэтому тип поля — `number | ''`. Нулевую цену нельзя отбрасывать
проверкой `if (value)`: 0 — допустимый фильтр.

`@submit.prevent` вызывает обработчик без перезагрузки страницы. HTML проверяет
минимум, максимум и шаг числовых полей, а обработчик отдельно проверяет
`minPrice <= maxPrice`. `defineEmits` описывает событие `apply`: через него
форма передаёт странице готовые параметры, аналог `@Output` в Angular.
Новые фильтры и сброс сразу запрашивают первую страницу. Кнопка обновления
и пагинация используют применённые параметры, даже если черновик уже изменён.

`URLSearchParams` в API-функции кодирует значения, включая пробелы и `&`, и
пропускает пустые параметры. Пример: `/api/products?search=North&size=42&max_price=8000&limit=13&offset=0`.
Фильтрацию выполняет БД через существующий бэкенд; фронтенд не фильтрует одну
загруженную страницу. `/api/brands` даёт варианты для списка брендов. Ошибка
брендов не блокирует каталог и остальные фильтры; есть отдельная кнопка повтора.

API возвращает массив без общего количества. Для страницы размера N запрашиваем
N+1 записей: показываем первые N, по дополнительной определяем доступность
«Далее». Смещение `(page - 1) * N`; число всех страниц не выдумываем.
`AbortController` отменяет предыдущий запрос и запросы при уходе со страницы;
отменённый ответ не может заменить актуальные данные. Ошибка следующей страницы
повторяется с тем же смещением. Фильтры пока не сохраняются в URL: перезагрузка
возвращает исходный каталог.
