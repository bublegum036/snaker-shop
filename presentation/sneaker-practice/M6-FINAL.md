## M6: что именно проверить

**Слои.** Проследите POST /orders: `schemas/orders.py` задаёт вход и ответ, `dependencies.py` проверяет JWT/User, `routers/orders.py` вызывает `services/orders.py`. Сервис владеет бизнес-операцией, а `services/unit_of_work.py` — контекстом новой Session и транзакции. Модели описывают таблицы. Каждый helper не должен получать свой commit.

**Ошибки.**401 — вход;403 — роль;404 — недоступный/неизвестный объект;409 — конфликт состояния;422 — форма;503 наhealth — БД недоступна. ShopError сначала проходит через rollback. Не ловите все исключения с ответом 200/400/409. Detail бизнес-ошибки — строка, валидации — списокloc/msg/type; возвращаемого input с паролем нет. Не публикуйте SQL/traceback/секреты в API-ответе.

**Настройки.** Полный requirements.txt устанавливается в новый venv. Старый базовый список сохранён отдельно. DATABASE_URL и JWT_SECRET приходят из .env или переменных процесса. `.env.example` содержит учебные значения. `.gitignore` полезен, но не удаляет уже отслеживаемые файлы и не гарантирует состав ZIP. Проверяется фактический комплект; аудит всей истории Git здесь не заявлен.

**README.** Весь путь есть в [готовой инструкции](README.md): окружение,конфиг,Docker,миграции,seed,финальный Uvicorn,администратор,проверки и остановка. `app.main:app` остаётся старой учебной точкой; финальная —`app.final_main:app`.

## Что доказал чистый запуск

Команда из корня проекта с активным venv и работающим учебным PostgreSQL:

```sh
python verify_final.py
```

[Код проверки](verify_final.py) выполнил:

1. Копирование исходников в новую временную папку без старых.env/.venv/кэшей.
2. Создание нового venv тем же Python, установку полного requirements.txt, pip check.
3. Создание новой пустой базы `final_check_<uuid>` на существующем сервере PostgreSQL.
4. Новый локальный.env, генерацию JWT_SECRET, CLI Alembic upgrade head, seed.
5. Проверку семи таблиц, ревизии 0001, исходных 2/3/4 строк каталога; повторный seed без изменений.
6. Настоящий Uvicorn финальной версии и **43 проверки**, включая вызовы всех 18 операций.
7. Повтор **85 M2–M3** и **76 M4–M5** проверок в новом venv. Они создают свои временные базы.
8. Остановку процессов, закрытие соединений, удаление только созданных БД и временной папки.

[Отчёт](final-verification.json) не сохраняет секреты и обновляется только после полного успеха. JS-копия используется слайдами. Сам `final_smoke.py` предназначен только для изолированной базы; запускайте внешний `verify_final.py`, который создаёт её. Проверка требует права создавать/удалять базы у учебного пользователя и доступа к установке пакетов.

Граница проверки: macOS,Python3.13.3, новый venv, пустая БД на **уже работающем** PostgreSQL. Это не установка Docker на новом компьютере, не тест Windows/Linux, не нагрузочный тест. `/docs` возвращает HTML, OpenAPI совпадает с картой, операции вызываются HTTP-клиентом. Сам интерфейс Swagger для личной сдачи ученик проходит вручную. UI-ресурсы Swagger по умолчанию приходят с CDN.

## Финальная демонстрация

Подробные запросы — вREADME. Для исходного seed:

| Шаг | Что показать |
|---|---|
|Регистрация/login|Успешные 201/200, затем /auth/me; токен вне кадра|
|Каталог|Товар 10, размер 101 stock3 price7990; товар 20, размер 201 stock5 price5990|
|Корзина|101×2 и 201×1; две строки, три пары; estimated_total21970.00|
|Оформление|POST /orders{},201, новый реальныйid,total21970.00,statuscreated|
|После покупки|Stock1/4; корзина пуста; свой заказ виден в истории|
|Изоляция|Борис получает 404 для чужого заказа; без входа 401|

Если данные уже менялись, сначала сверяйте состояние. Seed не возвращает предыдущие остатки. Не удаляйте рабочий том; проверочный скрипт воспроизводит исходные данные изолированно. Ручные кадры/видео должны показывать ваш проект, а не иллюстрацию слайда.

## Ошибки перед сдачей

Финальный HTTP-прогон проверил 9 отказов:нет токена 401;обычный пользователь пишет каталог 403;чужая корзина 404;quantity0,отрицательная цена и пустой email422;нехватка второй позиции 409;чужой заказ 404;обычный пользователь меняет статус 403. Для каждого сравниваются все семь таблиц до/после. Снимки совпали.

HTTP401/403 проверяется с корректным телом. После добавления корзины тест отдельно изменяет остаток второй позиции в своей временной БД:409 должен оставить **весь** заказ неоформленным. Проверки M4–M5 дополнительно доказывают три точки rollback и три HTTP-гонки; прямые вызовы ORM для внедрения сбоя не выдаются за HTTP.

## CONCEPT и комплект

[CONCEPT.template.md](CONCEPT.template.md) — вопросы и опоры, **не** готовый ответ от лица ученика. Заполните свой CONCEPT.md:API/REST,таблицы,checkout,слои,аутентификация. Код, документы и промпты готовы для обучения, но не означают, что за ученика выполнена его личная сдача.
