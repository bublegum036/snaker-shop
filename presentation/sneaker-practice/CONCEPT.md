# Мой разбор магазина

## 1. API, REST и группы эндпоинтов

API — это способ общения между фронтендом и бэкендом. Клиент отправляет
запросы для получения данных или выполнения действий, сервер возвращает
статус, заголовки и обычно тело ответа.

REST — стиль организации API вокруг ресурсов. В нашем магазине это товары,
корзина и заказы. GET используется для чтения, POST — для создания,
PUT/PATCH — для изменения, DELETE — для удаления.

Каталог позволяет посмотреть и найти товары. Корзина собирает выбранные
позиции перед покупкой. При оформлении сервер создаёт заказ, сохраняет
цены и сумму, уменьшает остатки и очищает корзину. Заказы можно посмотреть
в истории.

Аутентификация подтверждает личность пользователя, авторизация проверяет
его права. Каталог доступен без входа, корзина и заказы требуют токен,
управление каталогом — права администратора.

Например, GET `/products` возвращает страницу товаров, POST `/auth/login`
проверяет данные входа и выдаёт JWT, GET `/orders` возвращает личную
историю заказов.

## 2. База данных и связи

База данных хранит пользователей, каталог, корзины, заказы и остатки.
Данные сохраняются между перезапусками приложения и используются
централизованно. Бэкенд выполняет правила оформления и пополнения,
а БД сохраняет изменения и обеспечивает их целостность.

| Таблица | Что хранит |
|---|---|
| `users` | Пользователей |
| `brands` | Бренды |
| `products` | Карточки товаров и текущие цены |
| `product_sizes` | Размеры и остатки |
| `cart_items` | Позиции корзин и количества |
| `orders` | Владельца, статус, сумму и дату заказа |
| `order_items` | Позиции заказа и цены покупки |
| `checkout_requests` | Ключи идемпотентности и сохранённые ответы |

Первые семь таблиц относятся к заданию, восьмая добавлена для идемпотентности.

Один бренд может иметь несколько товаров, один товар — несколько размеров.
Остаток хранится у конкретного размера, чтобы учитывать их доступность отдельно.

Один заказ содержит несколько позиций. Общие данные находятся в `orders`,
позиции — в `order_items`, связанных через `order_id`. Так общие данные
заказа не дублируются.

Корзина и заказы связаны с пользователем через `CartItem.user_id`
и `Order.user_id`. У пользователя может быть несколько заказов.

`price_at_purchase` сохраняет цену покупки. Изменение цены в каталоге
не меняет сумму старого заказа.
