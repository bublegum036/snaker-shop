# Практика M0–M1: окружение, модели, миграция и seed

Запускаемый эталон для глав 11–12, слайды 121–136 [презентации](../sneaker-backend.html). В этом проекте реализованы настоящий `GET /health`, семь ORM-моделей, первая миграция и повторяемый seed каталога. Продолжение [M2–M3: каталог, регистрация и JWT](M2-M3.md) находится в том же проекте с отдельными точками запуска. Эта инструкция описывает M0–M1. Продолжение [M4–M5: корзина, заказ, откат и конкуренция](M4-M5.md) добавляет следующие точки запуска в том же проекте.

Два способа работы: запустить этот комплект и сверить результаты либо создать собственную папку `sneaker_shop` и последовательно выполнять шаги ниже с промптами. Готовый комплект уже содержит миграцию `0001`: повторно создавать initial в нём не нужно. Проверки проведены на macOS, Python 3.13.3, PostgreSQL 17; команды PowerShell приведены для повторения, но запуск на Windows не выполнялся.

## 1. Выбрать корень проекта и Python

Для готового эталона из корня репозитория:

```sh
cd presentation/sneaker-practice
```

Для самостоятельной сборки вместо этого:

```sh
mkdir sneaker_shop
cd sneaker_shop
```

Далее все команды выполняются из выбранного корня, где находятся `requirements.txt`, `compose.yaml`, `alembic.ini` и папка `app`. Не выполняйте команды в корне всей презентации.

macOS / Linux, bash или zsh:

```sh
python3 --version
python3 -m venv .venv
source .venv/bin/activate
```

Windows, PowerShell:

```powershell
py -3 --version
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

До создания окружения проверьте версию: нужна 3.11+. Если `py -3` или `python3` выбирает старую версию, укажите установленный подходящий интерпретатор явно. Если активация запрещена, используйте `.\.venv\Scripts\python.exe` вместо `python`; на macOS/Linux — `.venv/bin/python`. Менять системную политику PowerShell для этого не обязательно.

```sh
python -c "import sys; print(sys.executable)"
```

Путь должен указывать внутрь `.venv` данного проекта. В каждом новом терминале активируйте это окружение заново.

## 2. Подготовить зависимости и конфигурацию

В готовом эталоне файлы уже есть. Для своей сборки используйте [requirements-m01.txt](requirements-m01.txt) как проверенный список версий и изучите назначение зависимостей:

| Пакет | Роль в M0–M1 |
|---|---|
| FastAPI, Starlette, Pydantic | Приложение, HTTP и схемы |
| Uvicorn | Процесс HTTP-сервера |
| SQLAlchemy | Engine, сессии и ORM |
| psycopg, psycopg-binary | Драйвер PostgreSQL |
| Alembic | Версии схемы БД |
| python-dotenv | Загрузка локального `.env` |
| HTTPX | Настоящие HTTP-запросы проверочного сценария |

Остальные закреплённые пакеты — зависимости этих инструментов. Хэширование паролей и JWT добавляются в M3 согласно стеку задания; в M0–M1 они ещё не используются.

```sh
python -m pip install -r requirements-m01.txt
python -m pip check
```

Ожидается `No broken requirements found.`. Эта проверка не заменяет запуск сервера.

Создайте `.env` из [.env.example](.env.example) **один раз**, если своего файла ещё нет:

```sh
cp .env.example .env
```

В PowerShell:

```powershell
Copy-Item .env.example .env
```

В шаблоне только вымышленные локальные значения `practice / practice-only`, база `sneaker_shop`, порт компьютера `55433`. Строка подключения использует `postgresql+psycopg://…@127.0.0.1:55433/sneaker_shop`. Смена `DB_PORT` требует согласованной смены адреса в `DATABASE_URL`. Зарезервированные символы в своём пароле нужно кодировать для URL.

`.env`, `.venv/` и `__pycache__/` исключены через [.gitignore](.gitignore). В Git сохраняются шаблон, конфигурация и версии зависимостей. Compose читает `.env` для подстановки; Python загружает его отдельно в [config.py](app/core/config.py). Уже установленные переменные окружения имеют приоритет над файлом.

## 3. Запустить PostgreSQL

Промпт этого шага: `m01_compose` в [prompts.json](prompts.json). Он задаёт один сервис `db`, именованный том, healthcheck и локальный порт. Файл [compose.yaml](compose.yaml) — полный результат для сверки; фрагмент на слайде 124 сокращён.

```sh
docker compose config --quiet
docker compose up -d --wait
docker compose ps
docker compose exec db psql -U practice -d sneaker_shop -c "SELECT 1;"
```

Ожидается healthy для `db` и значение `1` от psql. Docker должен быть запущен. Имя Compose-проекта — `sneaker-practice-m01`; он не использует сервисы, базу и том теоретических глав на порту 55432.

Внутри контейнера PostgreSQL слушает 5432; компьютер обращается к 127.0.0.1:55433. Имя `db:5432` подходит другому контейнеру в той же сети Compose. API этой главы работает на компьютере.

Том `pgdata` переживает остановку контейнера. `POSTGRES_USER`, `POSTGRES_PASSWORD` и `POSTGRES_DB` инициализируют пустую БД при первом запуске; изменение `.env` не меняет уже существующий пароль роли. `pg_isready` проверяет готовность сервера, но не заменяет SQL-запрос из приложения. Для проверки синтаксиса используйте `config --quiet`, чтобы не публиковать раскрытые переменные в выводе.

## 4. Создать приложение и принять M0

Промпт: `m01_health`. Прочитайте три файла по пути запроса:

1. [config.py](app/core/config.py) читает `DATABASE_URL` из окружения/`.env`.
2. [database.py](app/database.py) создаёт общий синхронный Engine, фабрику сессий и задаёт таймауты.
3. [main.py](app/main.py) выполняет `SELECT 1` внутри `/health` и освобождает Engine при завершении приложения.

`connect_timeout=3` ограничивает установку подключения, `pool_timeout=3` — ожидание свободного соединения, `statement_timeout=3000` — SQL на PostgreSQL. Это разные ограничения, а не единый HTTP-дедлайн. `pool_pre_ping=True` помогает восстановить работу после устаревания соединений в пуле.

```sh
python -m uvicorn app.main:app --reload --port 8000
```

Оставьте процесс работающим. Откройте [Swagger](http://127.0.0.1:8000/docs), выберите GET `/health`, нажмите Try it out → Execute. Отдельно можно читать [OpenAPI JSON](http://127.0.0.1:8000/openapi.json). Интерфейс Swagger по умолчанию загружает JS/CSS с CDN; если сеть недоступна, сам API всё равно можно проверить HTTP-клиентом.

В другом терминале из **того же корня проекта**:

```sh
curl -i http://127.0.0.1:8000/health
docker compose stop db
curl -i http://127.0.0.1:8000/health
docker compose up -d --wait
curl -i http://127.0.0.1:8000/health
```

В Windows используйте `curl.exe` вместо неоднозначного псевдонима `curl`, либо отправьте запрос через Swagger.

| Состояние | HTTP | Тело |
|---|---|---|
| БД работает | 200 | `{"status":"ok"}` |
| Только БД остановлена, API работает | 503 | `{"status":"unavailable"}` |
| БД снова healthy, тот же API | 200 | `{"status":"ok"}` |

В ответ не попадают URL подключения, пароль или traceback. Код перехватывает ожидаемые ошибки доступности и ожидания пула, а не все исключения программы. `/health` проверяет соединение, **не наличие таблиц и не весь магазин**: M0 работает до миграции.

Автоматическое повторение этой проверки:

```sh
python http_smoke.py
```

Этот сценарий запускает настоящий Uvicorn на свободном локальном порту, сверяет конфигурацию с `sneaker-practice-m01`, останавливает **только его сервис db**, затем восстанавливает его в `finally`. Не запускайте его, пока в этом же учебном сервисе идёт другая работа. Итог: 6 проверок, 200 → 503 → 200; API-процесс сценария завершается, БД остаётся доступной. Сохранённый [HTTP-отчёт](http-verification.json) не содержит реквизитов подключения.

## 5. Нарисовать схему и написать модели M1

До кода нарисуйте семь таблиц и все поля исходного задания. [entities.py](app/models/entities.py) содержит полный вариант, [base.py](app/models/base.py) — общий Base, [models/__init__.py](app/models/__init__.py) — импорты всех классов.

| Шаг и промпт | Модели | Что проверять |
|---|---|---|
| `m01_catalog` | Brand, Product, ProductSize | Цена Decimal/Numeric, FK бренда и товара, UNIQUE товара/размера, stock >= 0 |
| `m01_users` | User, CartItem | Уникальный email, обязательный хэш, FK владельца, quantity > 0, UNIQUE пользователя/размера |
| `m01_orders` | Order, OrderItem | FK пользователя/заказа/размера, статус, total, время и снимок цены одной пары |

`ForeignKey` описывает ссылку в БД. `relationship` даёт переходы Python: `product.brand`, `product.sizes`, `user.cart_items`, `user.orders`, `order.items`. В схеме **семь FK**: products→brands, product_sizes→products, cart_items→users и product_sizes, orders→users, order_items→orders и product_sizes.

Выбранные договорённости: цены > 0, stock >= 0, quantity > 0, total >= 0; статусы `created`, `processing`, `completed`; `image_url` nullable, остальные основные поля обязательны. Время хранится с часовым поясом, `created_at` получает `now()` на сервере. Само редактирование моделей не изменяет БД. Фильтр владельца ресурса и логика покупки относятся к последующим модулям.

Проверка импорта после трёх шагов:

```sh
python -c "from app.models import Base; print(sorted(Base.metadata.tables))"
```

Ожидаются `brands`, `cart_items`, `order_items`, `orders`, `product_sizes`, `products`, `users`. В самостоятельной сборке после первого шага таблиц в metadata три, после второго — пять.

## 6. Создать и прочитать миграцию

Промпт: `m01_migration`. В **новой самостоятельной сборке**, когда Alembic ещё не настроен:

```sh
python -m alembic init alembic
```

Настройте [alembic.ini](alembic.ini) и [alembic/env.py](alembic/env.py): один источник подключения, импорт всех моделей и `target_metadata = Base.metadata`. Для первой генерации целевая учебная БД должна быть без таблиц приложения. Затем:

```sh
python -m alembic revision --autogenerate -m initial
```

Это создаёт кандидат файла, не таблицы. Прочитайте его целиком: семь `create_table`, все поля, семь FK, составные UNIQUE, CHECK, nullable, Numeric и server_default. Проверьте порядок создания и обратного удаления. Autogenerate не является доказательством корректности; `alembic check` тоже ограничен возможностями сравнения схемы.

В **готовом эталоне** [0001_initial.py](alembic/versions/0001_initial.py) уже существует и включает `image_url`. Здесь не повторяйте `init` и `revision`: переходите к применению.

```sh
python -m alembic upgrade head
python -m alembic current
python -m alembic check
```

Ожидается `0001 (head)` и отсутствие новых операций upgrade. Номер ревизии в самостоятельно сгенерированном проекте может отличаться. Не переписывайте уже применённые ревизии и не заменяйте Alembic вызовом `create_all` в startup. Помимо семи таблиц магазина появится служебная `alembic_version`.

## 7. Добавить и дважды запустить seed

Промпт: `m01_seed`. [app/seed.py](app/seed.py) вставляет каталог в одной транзакции: бренды → товары → размеры.

```sh
python -m app.seed
python -m app.seed
```

| Таблица | После первого запуска на чистой БД | После второго |
|---|---|---|
| brands | 2 | 2 |
| products | 3 | 3 |
| product_sizes | 4 | 4 |
| users, cart_items, orders, order_items | 0 в каждой | 0 в каждой |

| Product | Название | Цена | Размеры: остаток |
|---|---|---|---|
| 10 | North Runner | 7990.00 | 42: 3; 43: 0 |
| 20 | City Walk | 5990.00 | 41: 5 |
| 30 | North Trail | 9990.00 | 42: 2 |

Повтор вставляет отсутствующие ID, не сбрасывает существующие цены/остатки и не очищает таблицы. Конфликт по другому UNIQUE, например имени бренда с другим ID, даёт ошибку с откатом. Это seed известного учебного каталога, а не синхронизация произвольных пользовательских данных.

После явных ID скрипт продвигает Identity до занятых значений, не перемещая её назад. Пропуски ID допустимы. Сами строки после повторного запуска не меняются. Последовательности не обязаны откатываться как обычные строки транзакции.

Проверить данные можно через psql:

```sh
docker compose exec db psql -U practice -d sneaker_shop -c "SELECT id,name,price FROM products ORDER BY id;"
docker compose exec db psql -U practice -d sneaker_shop -c "SELECT product_id,size,stock FROM product_sizes ORDER BY id;"
```

## 8. Принять M1 на новой базе

Промпт: `m01_accept`. Для готового эталона:

```sh
python verify.py
```

Сценарий создаёт **новую отдельную БД** `m01_check_<uuid>` через настроенный локальный сервер. Нужны права CREATE DATABASE; учебная роль контейнера ими обладает. Данные рабочей базы и старых уроков не очищаются. В `finally` удаляется только созданная этим прогоном БД, после закрытия её соединений.

Итог: **25 проверок**:

- Чистая БД, upgrade с нуля, повтор upgrade, ревизия 0001, отсутствие расхождения моделей по Alembic check.
- Семь таблиц приложения, семь FK, денежный тип и обязательность цены, nullable image_url.
- Seed 2/3/4, повтор без изменения строк, сохранение вручную изменённого stock.
- Настоящий ORM-переход North Runner → North → размеры 42 и 43.
- 12 отказов БД: отрицательная цена, отсутствующий бренд, NULL имени, отрицательный stock, повтор размера, нулевое количество корзины, повтор позиции, отсутствующий владелец, отрицательный total, неверный статус, нулевое количество заказа, отрицательная цена покупки.
- Корректный ID обычной вставки после seed и откат временных строк проверок.

Проверки корзины/заказа создают свои временные связанные строки в транзакции. `IntegrityError` обрабатывается с откатом savepoint; в конце откатывается вся проверка. Эти строки не являются seed и не попадают в рабочую БД.

[verification.json](verification.json) содержит фактический результат. [verified.js](verified.js) и [http-verified.js](http-verified.js) передают сохранённые результаты автономной презентации. Переключатель на слайде 128 показывает HTTP-отчёт, а не управляет Docker.

M1 принят, когда вы показываете запуск с нуля и своими словами различаете модель, миграцию и seed. Сохраните актуальные файлы, команды и фактические результаты перед M2. Полный магазин пока не реализован.

## Остановить работу

В терминале API нажмите Ctrl+C. Затем из корня этого проекта:

```sh
docker compose stop db
```

Том сохраняется. Для следующего занятия достаточно `docker compose up -d --wait`. Проверять запуск с нуля можно через `verify.py`; удалять рабочий том командой `down -v` для этого не требуется.

Источники механизмов: [Python venv](https://docs.python.org/3/library/venv.html), [переменные Docker Compose](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/), [пул SQLAlchemy](https://docs.sqlalchemy.org/en/20/core/pooling.html), [Alembic autogenerate](https://alembic.sqlalchemy.org/en/latest/autogenerate.html), [жизненный цикл FastAPI](https://fastapi.tiangolo.com/advanced/events/).
