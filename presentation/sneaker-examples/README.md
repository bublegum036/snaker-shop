# Учебные примеры Python и FastAPI к главам 3 и 4

Этот комплект позволяет выполнить код из [презентации](../sneaker-backend.html#s-023), проверить вывод Python и отправить настоящие HTTP-запросы. Короткие программы иллюстрируют функции, структуры данных, типы, классы, исключения и Decimal. Отдельное приложение показывает маршруты, Pydantic, схемы ответа и Depends.

Примеры используют статические данные. Подключения к PostgreSQL, JWT и сохранения корзины или заказа здесь нет. Операции `/demo/*` нужны для объяснения механизмов; они не входят в контракт будущего магазина.

## Что проверено

Примеры выполнены на Python 3.13.3, FastAPI 0.141.1, Pydantic 2.13.5, Uvicorn 0.52.4 и HTTPX 0.28.1. Прямые зависимости зафиксированы в [requirements.txt](requirements.txt). Это отдельный набор для примеров, а не полный стек практического задания.

[verification.json](verification.json) содержит результат проверки Python и API через TestClient. [http-verification.json](http-verification.json) фиксирует проверку запущенного Uvicorn через настоящий HTTP: health, каталог, HTML Swagger, принятие и отклонение количества, фильтрация полей пользователя. В показе результаты обозначены как проверенные; интерактивные переключатели презентации используют записанные ответы, а не запускают Python в браузере.

## Подготовить окружение

Команды ниже выполняются из корня репозитория на macOS или Linux. Для подготовки нужен Python 3.11 или новее; фактическая проверка этого комплекта выполнена на версии, указанной выше.

```bash
cd presentation/sneaker-examples
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

На Windows можно использовать интерпретатор окружения напрямую, без активации. Из корня репозитория в PowerShell:

```powershell
cd presentation\sneaker-examples
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe verify.py
```

В остальных командах этого документа `python` означает интерпретатор созданного окружения. При использовании варианта без активации замените его на `.\.venv\Scripts\python.exe`.

## Выполнить код одного слайда

```bash
python run_example.py 23
```

Вывод для слайда 23:

```text
15980
```

Доступны номера 23, 24, 25, 26, 28, 29 и 30. Например, `python run_example.py 25` показывает различие числа и строки при вызове функции с аннотацией `int`.

Исходники этих небольших программ лежат в [snippets.json](snippets.json). `run_example.py` исполняет выбранную локальную программу. Поле `expected` содержит ожидаемый вывод для проверки. Скрипт не загружает и не запускает код из сети.

## Проверить весь комплект

```bash
python verify.py
```

Проверка запускает все короткие программы, сравнивает их вывод, отправляет запросы к учебным приложениям через TestClient и проверяет поведение. Сервер, Docker и база для этого шага не нужны. При успехе итоговый отчёт содержит `"passed": true`.

Проверяем наблюдаемое поведение:

- `/health` возвращает `200` и `{"status":"ok"}`; неверный метод и неизвестный путь дают `405` и `404`.
- Для количества `0`, `-1`, строки `"2"`, boolean `true` и дроби `1.5` возвращается `422`, тело обработчика не вызывается.
- Количество `2` проходит схему, обработчик получает проверенные данные.
- В ответе `/demo/user` есть только `id` и `email`, поле `hashed_password` отсутствует.
- Вход товара проверяет непустое имя и положительный Decimal с заданной точностью; выход добавляет ID и сериализует цену строкой.
- Зависимость принимает `limit=3`, подставляет `10` по умолчанию и отклоняет `51`.
- Подключённый роутер доступен по `/products`, читает карточку и отклоняет неизвестный ID.

После успешной проверки обновляются [verified.js](verified.js) и [verification.json](verification.json). Презентация берёт из `verified.js` точный код, вывод и записанные ответы. Если меняете пример, запустите проверку до открытия презентации.

Текущий набор зависимостей может выводить предупреждение Starlette о будущем переходе тестового клиента с `httpx` на `httpx2`. На указанном проверенном наборе это предупреждение, а не отказ проверки; замена зависимостей учебного задания для этого не требуется.

## Запустить минимальное приложение

В той же папке и окружении:

```bash
python -m uvicorn minimal:app --port 8000
```

`minimal` — файл [minimal.py](minimal.py), `app` — объект внутри него. Сервер занимает терминал до остановки. Откройте в браузере:

- [Проверка приложения](http://127.0.0.1:8000/health) — JSON `{"status":"ok"}`.
- [Swagger](http://127.0.0.1:8000/docs) — разверните `GET /health`, нажмите `Try it out`, затем `Execute`.

Читайте фактический раздел **Server response**. `Example Value` показывает образец из схемы и не доказывает выполнение запроса. Стандартный Swagger UI загружает свои JS и CSS с CDN; при недоступной сети сам API можно проверить напрямую. HTML-презентации доступ к сети не нужен.

Остановите сервер сочетанием `Ctrl+C` перед запуском следующего приложения на том же порту.

## Запустить примеры валидации и роутеров

```bash
python -m uvicorn demo:app --port 8000
```

В Swagger появятся дополнительные операции:

| Операция | Что попробовать | Что увидеть |
|---|---|---|
| `GET /products` | Выполнить без параметров | Два статических товара |
| `GET /products/{product_id}` | ID `10`, затем `999` | Карточка, затем `404` |
| `POST /demo/cart/items` | `{"product_size_id":101,"quantity":2}` | Проверенные данные, `200` |
| `POST /demo/cart/items` | Заменить количество на `0` | `422`, ошибка поля quantity |
| `POST /demo/cart/items` | Заменить количество на строку `"2"` | `422`, строгий целочисленный тип |
| `GET /demo/user` | Выполнить без параметров | Только ID и email |
| `POST /demo/products` | `{"name":"North Runner","price":"7990.00"}` | `201`, ID `10`, цена строкой |
| `GET /demo/page` | Без параметра, затем `limit=3` и `51` | `10`, затем `3`, затем `422` |

`/demo/cart/items` не добавляет запись в реальную корзину, а возвращает принятые данные. Счётчик `app.state.cart_handler_calls` служит только проверке вызова обработчика. `/demo/products` всегда использует демонстрационный ID `10`, без вставки в базу. `/demo/user` возвращает заранее заданный вымышленный профиль, без входа пользователя.
