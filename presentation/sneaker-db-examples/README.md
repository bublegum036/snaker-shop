# Примеры для глав 5–6

Отдельный учебный PostgreSQL для слайдов 043–072. Здесь можно воспроизвести таблицы, связи и SQL из [презентации](../sneaker-backend.html). Это учебные данные, а не реализация полного магазина. В практике M1 схему приложения создадим через SQLAlchemy и Alembic; ручной SQL здесь помогает понять работу базы.

## 1. Подготовить окружение

Нужны запущенный Docker с Compose v2 и Python 3.11+ для автоматической проверки. Python-пакеты для этих SQL-примеров не требуются: проверка использует стандартную библиотеку, а `psql` запускается внутри контейнера.

Из корня репозитория:

```sh
cd presentation/sneaker-db-examples
cp .env.example .env
docker compose config --quiet
docker compose up -d --wait
docker compose ps
```

Копирование `.env.example` нужно только при первом запуске. Если `.env` уже настроен, сохраняйте его. Все значения в шаблоне вымышленные и предназначены для локального урока. `.env` исключён из Git; `.env.example` можно хранить в репозитории.

Сервис `db` использует `postgres:17`. Имя Compose-проекта — `sneaker-chapters-56`, опубликованный порт — `127.0.0.1:55432`. На компьютере адрес базы — `127.0.0.1:55432`, в той же сети Compose — `db:5432`. Порт API 8000 здесь не запускается: стенд содержит только базу. В презентации `/health` показан как явно обозначенный псевдокод.

Если порт 55432 занят, измените `DB_PORT` и соответствующий порт в `DATABASE_URL` в своём `.env`, затем повторите `up`. Проверяющие команды ниже рассчитаны на учебную роль `lesson` и базу `sneaker_lesson`. Если изменили их, согласуйте параметры `psql` и константу `BASE` в `verify.py`.

## 2. Убедиться, что PostgreSQL выполняет запрос

```sh
docker compose exec -T db psql -X -U lesson -d sneaker_lesson -c 'SELECT 1;'
```

Ожидается одна строка со значением `1`. Это проверяет SQL через локальное соединение внутри контейнера. Оно не подтверждает доступность базы из Python на компьютере и не проверяет наличие таблиц магазина. Для M0 нужен отдельный запрос из самого API с его `DATABASE_URL`.

## 3. Запустить последовательность примеров

```sh
docker compose exec -T db psql -X -U lesson -d sneaker_lesson -f /lesson/lesson.sql
```

Скрипт открывает транзакцию, создаёт отдельную схему `sneaker_lesson_session`, семь таблиц и учебные записи. Затем выполняет SELECT, JOIN, INSERT, UPDATE и DELETE. В конце делает `ROLLBACK`, поэтому учебная схема и изменения не остаются в базе. Повторный запуск допустим. При ошибке `ON_ERROR_STOP` завершает psql, и незавершённая транзакция откатывается.

Части сценария:

| Файл | Что изучаем |
|---|---|
| `sql/schema.sql` | Все семь таблиц, типы, PK, FK, UNIQUE, NOT NULL, CHECK |
| `sql/seed.sql` | Одни и те же ID товаров, размеров, покупателей и заказа |
| `sql/read.sql` | Цена до 8000, сортировка, LIMIT |
| `sql/join.sql` | Товар + название бренда |
| `sql/change.sql` | Учебный бренд 99: добавить, переименовать, удалить |
| `sql/lesson.sql` | Запуск всех частей в одной откатываемой транзакции |

Чтобы попробовать свой SELECT, можно добавить его в `sql/lesson.sql` перед `ROLLBACK` и повторить команду. Это текстовый учебный скрипт; не подставляйте пользовательский ввод в SQL конкатенацией в настоящем API.

## 4. Повторить автоматическую проверку

```sh
python3 verify.py
```

Проверка каждый раз создаёт отдельную схему со случайным именем внутри откатываемой транзакции. Проверяются четыре выборки, три изменения строки, пять отказов ограничений, сохранение исторической цены и путь от позиции заказа до пользователя и бренда.

Ожидаемый итог:

```text
Verified: 7 tables, 4 queries, 3 mutations, 6 checks, order trace.
```

`verification.json` содержит результаты PostgreSQL, его версию и коды ошибок. `verified.js` содержит те же данные для автономной HTML-презентации. Переключатели слайдов показывают сохранённые проверенные результаты, а не отправляют SQL в работающую базу. Запуск `verify.py` обновляет оба файла; для обновления слайдов перезагрузите HTML.

## 6. Остановить стенд

```sh
docker compose stop db
```

Следующий `docker compose up -d --wait` снова поднимет базу. Именованный том `pgdata` сохраняет каталог данных PostgreSQL 17. Обычная остановка не требует удаления тома. Команда `down -v` удаляет данные тома, поэтому для повторения урока она не нужна.

`POSTGRES_USER`, `POSTGRES_PASSWORD` и `POSTGRES_DB` применяются при инициализации пустого каталога данных. Изменение `.env` при существующем томе не переименует роль или базу и не сменит пароль уже созданного пользователя.

Пояснения по адресу и порту есть в [документации Docker Compose](https://docs.docker.com/compose/how-tos/networking/), по хранению — в [документации томов Docker](https://docs.docker.com/engine/storage/volumes/), по ключам и ограничениям — в [документации PostgreSQL 17](https://www.postgresql.org/docs/17/ddl-constraints.html).
